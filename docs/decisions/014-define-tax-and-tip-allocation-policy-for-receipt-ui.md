# 014 - Define Tax And Tip Allocation Policy For Receipt UI

## Status
Accepted

## Context
`discord-api`의 receipt check UI는 사용자가 아이템을 선택하고, 그 선택 결과를 바탕으로 최종 정산 금액을 보여주는 흐름이다.

이번 단계에서 세금과 팁을 실제 정산 계산에 포함해야 했고, 특히 술 관련 특수세(`SST`, `SLT`)를 어떤 방식으로 나눌지에 대한 정책이 필요했다.

정책이 필요했던 이유는 다음과 같다.

- 일반 sales tax와 특수세는 성격이 다르다.
- `SST`, `SLT`는 술 아이템에 직접적으로 연결된 세금이므로, 술을 고르지 않은 사람에게까지 동일하게 나누면 불공평해질 수 있다.
- 술은 원래도 특수세가 추가로 붙기 때문에, 그 비용을 전체 참여자에게 넓게 전가하면 실제 소비와 부담이 어긋난다.
- 일반 tax 역시 고정 금액 균등 배분보다, 각 사용자가 고른 물품 가격 비율에 따라 나누는 편이 실제 구매 비중과 더 가깝다.
- tip은 매장/영수증/사용자 기대에 따라 “비율 배분”과 “균등 배분” 둘 다 요구될 수 있으므로 하나로 고정하기보다 owner가 선택 가능해야 한다.

또한 이 정책은 Discord UI에서 사용자에게 설명 가능해야 했고, check 공개 메시지에서 왜 어떤 사람이 어떤 tax/tip을 부담하는지 드러나야 했다.

## Options Considered
1. 모든 tax와 tip을 전체 참여자에게 균등 분배
- 구현은 가장 단순하다.
- 하지만 술 특수세까지 전체에게 나누게 되어 소비와 부담이 크게 어긋난다.
- 술을 고르지 않은 사람도 `SST`, `SLT`를 부담하게 되어 공정성이 낮다.

2. 모든 tax와 tip을 전체 참여자에게 비율 분배
- 일반 tax에는 어느 정도 자연스럽다.
- 하지만 `SST`, `SLT`까지 비술 구매자에게 분배되는 문제는 그대로 남는다.
- 특수세의 원인 아이템이 무엇인지가 계산에 반영되지 않는다.

3. 일반 tax는 전체 선택 아이템 기준 비율 분배, `SST`/`SLT`는 술 아이템 선택자에게만 비율 분배, tip은 모드 선택 가능
- 일반 tax는 전체 소비 비중에 따라 나뉘어 비교적 공정하다.
- 술 특수세는 술 아이템과 연결된 소비자에게만 귀속되어 정책 설명이 쉽다.
- tip은 상황에 따라 비율/균등 둘 다 지원할 수 있다.
- 구현과 UI가 더 복잡해지지만, 실제 영수증 정산 기대치와 가장 잘 맞는다.

## Decision
다음 정책을 채택한다.

- 일반 `Tax`는 사용자가 선택한 전체 아이템 금액 비율에 따라 분배한다.
- `SST`, `SLT` 같은 술 관련 특수세는 술 아이템을 선택한 사람들끼리만 분배한다.
- `SST`, `SLT` 내부 분배도 각 사용자가 선택한 술 아이템 가격 비율에 따라 계산한다.
- tip은 receipt-level 값으로 다루고, owner가 check 단계에서 다음 두 방식 중 하나를 선택할 수 있게 한다.
- tip proportional mode:
  사용자가 선택한 전체 아이템 금액 비율에 따라 분배한다.
- tip equal mode:
  하나 이상 아이템을 선택한 참여자들끼리 균등 분배한다.

이 정책을 UI에도 반영한다.

- 공개 check 메시지에는 owner 전용 `Mark Alcohol` 버튼을 둔다.
- owner는 private selection panel에서 여러 아이템을 alcohol 항목으로 지정할 수 있다.
- alcohol로 지정된 아이템은 공개 메시지에서 식별 가능하게 표시한다.
- 공개 check 메시지에는 `Tax` 섹션과 `Tip` 섹션을 추가한다.
- `Tax` 섹션은 사용자별 부담 내역을 일반 tax, `SST`, `SLT`로 나눠 보여준다.
- `Tip` 섹션은 사용자별 팁 부담 금액을 보여준다.
- 헤더에는 실제 영수증에 값이 있는 경우에만 `SST`, `SLT`, `Tip`을 노출한다.

## Consequences
긍정적 결과:

- 술 관련 특수세가 실제 술 구매자에게만 귀속되어 공정성이 높아진다.
- 일반 tax도 소비 비중에 따라 나뉘므로 “왜 내가 이 금액을 내는지” 설명하기 쉽다.
- tip을 하나의 방식으로 강제하지 않아 실제 사용 시나리오를 더 잘 수용한다.
- 공개 메시지에서 `Tax`와 `Tip`을 분리해 보여주므로 정산 근거가 더 투명해진다.

부정적 결과 및 비용:

- parser contract, session state, settlement 계산, Discord UI를 함께 바꿔야 해서 구현 범위가 커진다.
- 술 아이템 식별이 parser 자동 판별만으로 충분하지 않을 수 있어 owner 수동 지정 UI가 필요하다.
- owner가 alcohol 항목을 지정하지 않으면 `SST`/`SLT` 정산이 성립하지 않으므로 추가 검증이 필요하다.
- tip 모드 토글이 들어가면서 check 단계 상호작용 수와 상태 복잡도가 증가한다.

## Follow-up Notes
- 이 결정은 receipt check 공개 메시지 기반 UI 흐름 위에서 동작한다.
- 관련 UI 방향은 `011-discord-selcetion-ui.md`를 함께 참고한다.
- 향후 parser가 alcohol item 판별 정확도를 높이면 owner 수동 alcohol 지정 의존도를 줄일 수 있다.
- tip 입력/수정이 parser payload만으로 부족해지면, 이후 owner-editable tip 정책을 별도 decision으로 분리할 수 있다.
